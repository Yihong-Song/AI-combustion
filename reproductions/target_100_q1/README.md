# 至少 100 篇 JCR Q1 燃烧 AI 论文复现

用户目标：至少 100 篇，重点燃烧本体、反应流、燃烧器/发动机、实验室诊断与控制，排除全球或大区域野火、遥感灾情与气候分析。JCR 采用期刊可核验年度的最佳类别，并明确类别；不能仅凭中文“一区”或 SJR 标签代替。

**当前严格验收仍为 0/100。** [progress.json](progress.json) 与 [queue.csv](queue.csv) 是工作台，不是已完成清单。候选数量不等于开源数量，也不等于复现成功数。

## 单篇怎样验收

1. 以 DOI 去重；期刊正式发表，具有可追溯的 JCR 年度、类别和 Q1 证据。
2. 阅读全文，指定一张有代表性的原文图/表及其模型、数据、切分、训练预算和指标。预印本与期刊最终版必须核对差异。
3. 固定作者源码和数据版本；如独立实现，提供公式/模块对应表与缺失细节的假设。
4. 实际执行训练或原文推理协议，保存环境、命令、输入哈希、预测、日志、失败与修改。
5. 按同口径计算指标，列出原文值、本地值、偏差与适用范围；不足以复现的结果保留失败/部分复现状态。

同篇的多个算例、种子或消融只计一篇。仅下载源码、跑通简单演示、重做一个通用模型，均不增加完成数。

## 本地与服务器

本机有 AMD Radeon RX 9060 XT；现有 Windows Python 使用 `torch 2.13.0+cpu`。GPU 存在与当前训练环境可用是不同事实，不能用 `torch.cuda.is_available()==False` 判断没有显卡。AMD GPU 可通过 ROCm 等支持环境训练，不依赖 NVIDIA CUDA。

对当前具体安装需验证 GPU 识别、矩阵运算、优化器、二阶自动微分和 float64；只有识别成功还不足以确认 PINN 可训练。查看 [硬件诊断](../../docs/LOCAL_COMPUTE.md)。用户预计提供向日葵服务器连接；连接尚未建立。远程桌面可用于交互，长任务宜在服务器保存脚本、日志和断点，优先考虑 SSH/SFTP。
